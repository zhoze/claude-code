# AEGIS

Local-first personal AI platform on an NVIDIA DGX Spark (DGX OS), built so
that **nothing leaves the box unless you explicitly release it — enforced by
the kernel and the OS, not by a model's good behaviour.**

This repository is the implementation tier. The architecture tier is the 18
parts under `docs/`; the parts revised here supersede their originals. This
tree is the **amended** edition — every change from the original is listed
with its reason in `AMENDMENTS.md`.

---

## Install: scan → compare → amend → install

Nothing installs blind. The flow is gated on a scan of the actual machine:

```bash
git clone <your-private-repo> ~/aegis-src && cd ~/aegis-src

# 0. Read. Nothing runs yet.
less docs/part-00-threat-model.md
less docs/part-17-roadmap.md
less AMENDMENTS.md

# 1. SCAN — read-only profile of THIS machine
./scan/aegis-scan.sh          # sudo for richer detail

# 2. COMPARE — machine vs. the install code's assumptions
./scan/aegis-compare.sh --write-overrides
#    Zero FAILs required. For anything flagged (or for a second pair of
#    eyes), run Claude Code on the box: see scan/REVIEW-WITH-CLAUDE.md

# 3. AMEND — fix code or machine, then re-run steps 1-2 until clean

# 4. INSTALL — guided, resumable, verified per phase
sudo ./install.sh
```

`install.sh` runs the phases in `bootstrap/` in order, records state in
`/var/lib/aegis/install-state` (a reboot or dropped SSH session costs
nothing — run it again and it resumes), and verifies each phase's
postconditions before moving on. `sudo ./install.sh --status` shows where
you are.

The phases:

| # | Phase | What it does | Stops for |
|---|-------|--------------|-----------|
| 00 | preflight | read-only checks | **D1**: typed acknowledgement if no disk encryption |
| 01 | users-and-dirs | 6 service uids, `/aegis` tree, approval queue | — |
| 02 | packages | apt set incl. build toolchain, rsync, age | — |
| 03 | python-env | venv, gate + core code, configs, nft **template** staged | — |
| 04 | credentials | API keys → `systemd-creds` (skippable) | key entry |
| 05 | egress-gate | firewall behind a **3-minute auto-rollback**, Gate, full verify | typed `CONFIRM` while your SSH session still works |
| 06 | models | llama.cpp build (CUDA, CPU fallback), GGUF download **through the gate**, sha256 → models.toml, llm+embed services | model choice, checksum confirmation |
| 07 | knowledge | Qdrant (own uid), ingestion, zone drop-ins, registry check | **D3**: GDPR acknowledgement |
| 08 | storage-backup | logrotate, timers, first verified snapshot | — |
| 09 | scaffold | Core stub + agent units installed, **nothing enabled** | — |

## The one idea

```
        Core, agents, models          ← asked to behave
   ═════════════════════════════      ← trust boundary
        Egress Gate, isolation        ← enforce
```

`aegis-proxy` is the only uid the kernel lets open an outbound socket to the
public internet. High-trust agents — the ones that read your CF&S data —
have no route to the Gate at all.

Releasing anything to a cloud model takes a command you type:

```bash
aegis-approve api.anthropic.com --reason "summarise the blade-yard note"
```

Single use — one token authorises one connection, burned before the socket
opens. 120-second default TTL. Minting requires `aegis-operators`
membership, which no agent and no AEGIS service holds (the Gate's
membership is read-and-burn on the queue, and anything the Gate could mint
it could equally just honour — Core and the agents cannot touch the
directory at all).

## Daily operation

```bash
aegis-approve --list                        # what is outstanding
aegis-approve --revoke-all                  # end of session, always
jq -c 'select(.event=="deny")' /aegis/logs/egress/audit.jsonl | tail -20
sudo ./tests/verify-egress.sh               # after every policy change
systemctl status aegis-egress-gate aegis-llm aegis-embed aegis-vectordb
```

(The audit log is operator-readable by design — `aegis-operators` group.)

## Rules that hold regardless of convenience

1. No secret in this repository, in `/aegis/config`, in a shell command, or in
   a chat window. `systemd-creds` or nothing.
2. Never widen the allowlist to fix a broken service without understanding
   what you are opening — then write the note.
3. `verify-egress.sh` must report zero failures before you build on top of
   the boundary.
4. Pin versions and record what you built (`/etc/default/aegis` carries the
   llama.cpp tag and the Qdrant version+hash; `models.toml` carries every
   model). Never track `main` on anything the security model rests on.
5. AEGIS uses its own identities, never yours.
6. Everything fails closed: undeclared trust zone, unlisted host, missing
   approval, unparseable config, unburnable token, unverifiable model.

## Status

**Installable now (phases 00-09):** the scan/compare gate, service
identities, packages, the nftables policy (applied behind an auto-rollback),
the Egress Gate with a working approval flow, llama.cpp serving a general
model on :8000 and embeddings on :8001, Qdrant on :6333 under its own uid,
a complete extract→embed→index ingestion path, backup/verify/reconcile
timers, and honest scaffolding for Core and the agents.

**Scaffolded, needs your build (phases 5-10 of the roadmap):** Core's task
loop and decision log (`aegis_core/service.py` is a stub and says so), the
research agent's tool surface, OCR in the ingest pipeline, voice, home
automation.

The order matters more than the completeness. The boundary phase gates
everything, and it is the part that is finished — and now actually passes
its own verification on a clean box.
